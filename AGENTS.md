# Project agent memory

- The plugin never edits Strata's sources: changes go to the Strata fork whose commit `strata.lock` pins (the stage split across machines lives there, `src/program/stage_link.hpp`). `cmake/pom-static-cuda.cmake` (passed with `-DCMAKE_PROJECT_INCLUDE`) swaps CUDA::cudart/cublas/cublasLt for the static libraries, and `runtime/pom_strata_server.py` adds `/pom/generate` by wrapping `serve.server.make_handler`. Keep both outside Strata's tree.
- The engine must link no CUDA shared library (`docker/build-runtime-in-container.sh` refuses it): a POM node image only has the driver. Build the runtime in the POM's own CUDA image (`docker/runtime.Dockerfile`); the Python packages target the node image's Python 3.12. The runtime also carries `engine/strata-vision`, the image encoder built for the CPU (a deployment with a projector runs it there, `engine.rs`). The HIP runtime (`--hip`, `docker/runtime-hip.Dockerfile`) cannot be static: it carries the ROCm libraries in its `lib/` and the plugin puts them on `LD_LIBRARY_PATH` (`runtime::Backend`, chosen per load from the POM's `gpu_devices`).
- `query` must return at once. Every child process (pack tool, Strata's server) is started from the manager thread in `src/engine.rs`, in its own process group with the parent-death signal; starting one from a short-lived thread would kill it when that thread ends.
- Some deployment settings are the plugin's, not Strata's editable keys: `src/engine.rs` takes them out of `settings` before the bridge applies Strata's rules. `kv_cache` becomes `--kv`, `conversation_cache_mib`/`conversation_cache_slots` become `--conversation-cache-mib`/`--conversation-cache-slots` (whole-model machines only, never a stage of a split), and the bridge pops `session_save` itself.
- The plugin host uses its own stdin/stdout for IPC: children get `Stdio::null()` and write to `<plugin dir>/run/strata-server.log`.
- `engine.*` operations are for the local POM node only (`engine.link` gives an earlier stage's loopback port and secret, which the POM hands only to the next stage's machine); the API key leaves the library only through `engine.upstream` and is never in `rpc.status`, `host.services`, logs or the screens. `src/proxy.rs` adds it on the way to Strata and drops the browser's credentials, `Origin` and `Referer`.
- The generation contract with the POM gateway (`/pom/generate`, NDJSON `t` answer text / `r` reasoning / `p` / `done` / `error`) is documented in the POM repository, `docs/subsystems/inference.md` section 7.1 (with the prefill/decode split: `inference_role`, `prefill_only`, `decode_holds`, `session_source`). Keep reasoning structured; do not flatten it into `<think>` text. Change both sides together.
- `ui/src/host/runtime.ts` and `ui/src/host/ready.ts` are the only places that touch `__POM_HOST__`. Class names use the `pb-` prefix, which `ui/build.mjs` renames to the plugin code.
- `ui/src/host/ready.ts` - the "finished rendering" signal the POM waits for (host version 6, `__POM_HOST__.ready()`). The POM mounts the screen hidden (`.pom-plugin-pending`) under its pieces animation and only opens it when this signal arrives or its short wait ends: a plugin without the signal keeps working. `useScreenReady(ready)` sends it once per mount, when the first status answer settles in `StrataApp` - not on the first render. An older host has no `ready`: the call is skipped.
- The POM's local development rebuild runs `development.rebuild` from `ui/manifest.json` (`scripts/dev-ui.sh`) with the source read-only: it builds the UI in `POM_PLUGIN_OUT_DIR`, where `build.rs` takes it. It does not touch `build/runtime`: after changing `runtime/pom_strata_server.py`, run `scripts/build-runtime.sh` (or `install -m 0644 runtime/pom_strata_server.py build/runtime/`) on the machine, or Strata keeps running the old bridge.
- Checks: `cargo test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `scripts/build-ui.sh`. A runtime change: `scripts/build-runtime.sh`, then run `runtime/pom_strata_server.py --engine mock` inside the POM image to check the route without a GPU.
